## Node bootstrap: from EK certificate to node SVID

```mermaid
flowchart TD
    t1["1. banlieue publishes the member's vTPM EK certificate on VirtualMachine.status (banlieue ADR-0045) before GuestReady."]
    t2["2. The watcher computes sha256(DER SubjectPublicKeyInfo) of the EK, which is the tpm attestor's agent ID hash, and declares mediatore-node-<ek-hash> parented to that agent."]
    t3["3. The controller manager renders the node entry; it waits in the server until the agent attests."]
    t4["4. The VM's agent attests with the EK; on sync it receives the node entry and issues the node SVID to the guest role (unix:uid:0 and the path of the one mediatore binary)."]
```

## A policy bundle, verified and compared in shadow

How notaio's reviewed policy reaches the broker and what the broker does with it in shadow, the default: observe and report, never admit, refuse or mint differently (ADR-0026). ADR-0030 and ADR-0040 add the enforcing mode.

```mermaid
flowchart TD
    t1["1. notaio compiles the SandboxPolicy, signs the bundle with its transit key and writes <policy>-bundle in the policy's namespace."]
    t2["2. The broker's reflector sees the ConfigMap and verifies the envelope against policy.trusted_keys at the current time; a bundle that fails is logged with its reason and goes no further."]
    t3["3. notaio's floor rule decides from the held floor (the same uid never goes down; a new uid only if issued after the held one); the store writes the next floor to its PolicyFloor resource only if the held one is still what was read, a compare-and-set on resourceVersion (ADR-0034), and a replica that lost the race reads and decides again."]
    t4["4. Only after the write succeeds does the verified payload enter the cache; each sandbox naming the policy is reconciled, the name resolved only in the sources of the sandbox's namespace (policy.sources, ADR-0054; P011 outside them, P012 when two hold it), every gap between the broker's configuration and the bundle is logged with its code, and PolicyConformant is set True, False with the codes, or Unknown while no bundle has been read."]
    t5["5. In shadow (policy.egress: shadow, the default) tokens are minted exactly as before: the comparison changes no admission, no claim and no mint. Under policy.egress: enforce the bundle's servable direct egress is served at the gateway (ADR-0030) and a gateway-placed audience must be one the policy admits (ADR-0040)."]
    t1 --> t2 --> t3 --> t4 --> t5
```

## A private image pulled with the person&#x27;s own credential, which the VM never sees (ADR-0043)

From the person's prompt to the first layer, for a registry that is a placed audience: the credential is sealed with OpenBao transit in the broker, placed by the gateway as Basic on each registry request, and the pool VM holds neither it nor any token derived from it.

```mermaid
flowchart TD
    t1["1. The CLI asks for the user name and secret at the echo-off prompt (or reads the saved item, whose age limit is the claim's TTL) and sends them in POST /v1/claims delegations, as ADR-0041."]
    t2["2. The broker seals the credential with the transit key derived from the claim's UID and stores only the ciphertext in the claim's Secret; the claim names an image on a registry that is a placed audience, so the claim must carry a delegation for it."]
    t3["3. The guest starts the claim's egress proxy first, then pulls through it on the route only root can open; the requests carry no credential."]
    t4["4. The proxy sends each request in origin form to a gateway's inject port over the claim's mutual TLS."]
    t5["5. The inject Envoy asks the authorizer, which obtains the credential from the broker over the gateway SVID (rel-gateway-mediatore-credential) and answers with Authorization: Basic."]
    t6["6. The inject Envoy originates TLS to the registry and streams the manifest and the layers back; the guest verifies every digest as ever (ADR-0021)."]
    t7["7. When the claim is released the broker deletes the sealed envelope's Secret; the authorizer's copy leaves memory with the claim."]
    t1 --> t2 --> t3 --> t4 --> t5 --> t6 --> t7
```

## A one-shot workload&#x27;s output read back by its owner (ADR-0045)

From the opt-in on the claim to the owner reading the finished workload's output: capture and redaction in the VM, batches over the node SVID, the Secret ring at the broker, the owner's NDJSON read, the sweep.

```mermaid
flowchart TD
    t1["1. mediatore sandbox create --logs: the claim carries workload.logs: true; a broker with logs.enabled false refuses it 501 before anything is created."]
    t2["2. GET /v1/me returns the workload with logs: true; the guest spawns nsjail with piped stdout and stderr, redacts each line in the VM, writes it through to the console and queues it with a sequence number."]
    t3["3. POST /v1/me/logs on the leading edge (at once after a quiet half second, otherwise every half second, or at 32 KiB; a line that has not ended goes as a partial record) over the node SVID through the control relay; the broker checks the node is the claim's, the opt-in, the shape, the size and the rate (two batches a second), stores the batch and wakes the claim's followers."]
    t4["4. The batch is appended to the claim's Secret ring; a retried batch is a no-op; the oldest segment goes when the cap is reached and the dropped bytes are counted."]
    t5["5. The workload exits under its restart policy: the guest flushes the queue (five seconds at most), then POSTs /v1/me/exit and the claim is released (ADR-0033)."]
    t6["6. mediatore sandbox logs <name>: the owner reads the stored output as NDJSON (stdout lines to stdout, stderr to stderr, a gap or a truncation one line on stderr) for the retention window after the claim ended; another subject is 403."]
```

## A claim&#x27;s image pulled through its own proxy and a gateway, under its namespace&#x27;s policy (ADR-0063)

The default pull in a gateway-era environment: the registry is a role: registry audience the claim's namespace was granted, the pull is decided by the authorizer like any other egress, and no path from the pool VM to a registry skips it.

```mermaid
flowchart TD
    t1["1. The broker resolves the claim's audiences from its namespace's bundles and refuses the claim (400 registry_not_granted) unless a role: registry audience in that set covers the image's registry."]
    t2["2. GET /v1/me hands the guest the registry route for the pull, apart from the workload's routes."]
    t3["3. The guest starts the claim's egress proxy, then pulls through its pull listener; the route's rules are applied to each request."]
    t4["4. The proxy opens a CONNECT tunnel to the registry through a gateway's data port under the claim's SVID."]
    t5["5. The authorizer checks the registry's host:port against the claim's allowlist (broker or cache) and admits or refuses the tunnel."]
    t6["6. Envoy connects to the registry and relays the bytes; the proxy's TLS with the registry carries the manifest and the layers, each verified against its digest by the guest (ADR-0021)."]
    t1 --> t2 --> t3 --> t4 --> t5 --> t6
```
